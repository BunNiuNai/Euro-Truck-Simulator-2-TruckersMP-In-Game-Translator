# ETS2 翻译器 v1.6.0 多特性设计文档

> 日期: 2026-07-21 | 版本: v1.6.0

---

## 概述

本次更新包含 5 项改动，涉及翻译引擎策略、UI 提示词、发送语言选择、消息语言标签、以及语言选项显示统一。

---

## 改动 1: Provider 模式切换（竞速 vs 顺序）

### 需求
在现有"并行竞速"基础上，新增"顺序超时回退"模式，用户可在设置中切换。

### 设计

**新增配置字段** `AppConfig.provider_mode: str = "race"`

| 值 | 行为 |
|:---|:---|
| `"race"` | 现有行为：所有启用的 Provider 并行请求，谁快用谁 |
| `"sequential"` | 按 Provider 列表顺序逐个尝试，单个超时 5s 或失败 → 自动尝试下一个 |

**顺序模式详细逻辑** (`translator.py: _call_api_internal`):

```
for provider in active_providers (按列表顺序):
    try:
        result = _call_provider(provider, text, timeout=5.0)
        return result  # 成功
    except (ConnectError, TimeoutException, HTTPStatusError 429):
        continue  # 超时/限速/不可用 → 下一个
    except (HTTPStatusError 401/403):
        continue  # 认证失败 → 下一个（可能是不同服务商）
    except Exception:
        continue  # 其他错误 → 下一个

# 全部失败 → 走现有串行重试逻辑（间隔 180ms 全部重试一遍）
```

**与现有熔断机制的协作**: 顺序模式下熔断照常生效——冷却中的 Provider 会被跳过，若全部冷却则强制重试全部。

**设置面板**: API 配置页新增一对 RadioButton：`竞速模式 (Race)` / `顺序模式 (Sequential)`。

**涉及文件**:
- `config.py`: AppConfig 新增 `provider_mode: str = "race"`
- `translator.py`: `_call_api_internal` 新增顺序分支；Provider 请求增加 5s 超时
- `main.py`: SettingsDialog API tab 新增模式选择 RadioButton

## 改动 2: 翻译提示词按后端类型区分

### 需求
根据实际使用的翻译后端显示不同的通知文案。

### 设计

**改动点**: `overlay.py: poll_messages()` 方法

当前代码无条件显示 `"大模型翻译了 X 条消息"`。改为根据 `self.cfg.translation_backend` 判断：

| 后端 | 提示文案 |
|:---|:---|
| `"llm"` | `大模型翻译了 X 条消息` |
| `"baidu"` | `百度翻译了 X 条消息` |
| `"llm+baidu"` | `大模型+百度翻译了 X 条消息` |

**涉及文件**: `overlay.py` (仅一处改动)

## 改动 3: 发送目标语言选择

### 需求
用户在翻译器输入中文发送到游戏时，可选择翻译成哪种语言（不限于英文）。

### 设计

**新增配置字段** `AppConfig.send_target_language: str = "en"`

**语言选项** (与接收翻译的 10 种语言一致，显示名改用中文全称——见改动 5):

| 中文显示 | ISO 639-1 代码 |
|:---|:---|
| 简体中文 | zh-CN |
| 英语 | en |
| 日语 | ja |
| 韩语 | ko |
| 法语 | fr |
| 德语 | de |
| 西班牙语 | es |
| 俄语 | ru |
| 葡萄牙语 | pt |
| 意大利语 | it |

**设置面板**: API 配置页新增 `Send Language / 发送目标语言` 下拉框，默认 `英语`。

**翻译逻辑变更**:
- `translator.py`: `translate_to_english()` 重命名为 `translate_for_send()`，接收 `target_lang` 参数
- LLM 翻译: 根据 `send_prompt.txt` 中的目标语言占位符动态替换，或使用 LLM 自身的目标语言参数
- 百度翻译: `translate_to_english_via_baidu()` 改为接收 `to_lang` 参数
- 发送流程 (`overlay.py:_do_translate`) 传入 `cfg.send_target_language`

**注意**: `send_prompt.txt` 目前硬编码 "Translate Chinese into natural, accurate English"。需要在 prompt 中动态替换目标语言名。实现方式：在 `get_send_prompt()` 返回的 prompt 中增加 `{target_language}` 占位符，调用时用 `cfg.send_target_language` 对应的中文名替换（或保留 prompt 模板不变，LLM 的 system prompt 中指明目标语言）。

**涉及文件**:
- `config.py`: AppConfig 新增 `send_target_language`
- `translator.py`: 重命名函数、参数化目标语言
- `main.py`: SettingsDialog 新增发送语言下拉框
- `overlay.py`: `_do_translate` 调用适配

## 改动 4: 消息语言标签

### 需求
每条翻译消息前显示 `[中文全称]` 标签，标注原始消息的语言。

### 设计

**新增配置字段** `AppConfig.show_language_label: bool = True`

**新增字段** `DisplayMessage.detected_language: str = ""`

**语言检测策略** (优先级从高到低):

1. **LLM API 返回源语言** — 部分 Provider 在响应中会标注检测到的源语言。调用时可以在 prompt 中要求 LLM 在翻译结果前返回源语言代码。实现：在接收 prompt 中加一条指令，让 LLM 在译文前标注 `[LANG:xx]`，解析时提取。

2. **字符集启发式检测** — 基于 Unicode 范围：
   - 西里尔字母 (U+0400-U+04FF) → `俄语`
   - 日文假名 (U+3040-U+309F, U+30A0-U+30FF) → `日语`
   - 韩文 (U+AC00-U+D7AF) → `韩语`
   - 中文汉字 (U+4E00-U+9FFF) → 根据 `target_language` 判断：若目标是中文则为源语言编码，否则为 `中文`
   - 泰文 (U+0E00-U+0E7F) → `泰语`
   - 阿拉伯文 (U+0600-U+06FF) → `阿拉伯语`
   - 拉丁字母为主 → 根据常见词/字符特征进一步区分（德语有 ß/ü/ö/ä，法语有 ç/è/é/ê，西班牙语有 ñ/¿/¡ 等），无法区分时 fallback `英语`
   
3. **Fallback** — 无法判断 → `未知`

**显示格式**: `[英语] PlayerName: Hello → 你好`

**设置面板**: 外观页新增 CheckButton `Show Language Label / 显示语言标签`

**涉及文件**:
- `config.py`: AppConfig 新增 `show_language_label`
- `message_types.py`: DisplayMessage 新增 `detected_language`
- `translator.py`: 新增 `_detect_language()` 函数；翻译流程中注入语言检测
- `overlay.py`: `_insert_one_at` / `_sync_display` 渲染语言标签
- `message_display.py`: 同步适配（如果 overlay 改为使用 message_display）
- `main.py`: SettingsDialog 外观页新增开关
